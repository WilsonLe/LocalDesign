# Connecting an external agent

Try the agent host’s built-in browser and page-tool discovery before opening Chrome, unless the user chose a browser or already attached a LocalDesign tab. Fall back only when the built-in browser is unavailable or lacks the required capability, explaining the observed reason; check the connection state and retry discovery before switching after a discovery failure. Working copies are browser-local: preserve existing work with a native export or resolve unsaved storage errors, then rediscover tools and inspect the destination document/revision before editing. The same URL does not transfer a working copy between browsers.

Open the deployed app in a browser host that supports `document.modelContext.registerTool`. The desktop built-in browser used during development supports site-tool discovery. Ordinary browsers can edit without WebMCP; the Connect agent dialog explains the current registration state. A standard MCP host can optionally use the explicitly connected [loopback stdio companion](local-mcp.md). There is no hosted HTTP MCP endpoint, provider token, in-app chat or built-in agent.

Ask the external agent: “Discover this page's tools, call localdesign_list_skills, read getting-started using localdesign_get_skill, then help me design …”. Runtime tool names may have a browser-generated suffix: use exactly the names returned by the host's discovery API. Guides refer to canonical names. The served instructions include the complete tool loop, model, boundaries, recovery and examples. UI design and typography packages require no prior plugin knowledge or network checkout.

At `/LocalDesign/`, no document is open (`workspace.status.documentOpen` is false). The status identity/revision guard is available for create/open/import commit; inspection also reports documentOpen. Document editing/export tools return NO_DOCUMENT until a workspace opens. Workspace create/open/import/save_copy synchronize `/LocalDesign/workspace/<document-id>` with the visible document. Guarded workspace close saves first, returns to the root list, and retires the prior tool registration and artifacts. Switch operations commit any focused UI draft before checking guards and again after asynchronous save/font work before replacement. If the draft advances revision, the old tool guard rejects with STALE_REVISION; re-inspect and retry with a fresh guard. Skills and catalog remain available on the list; rediscover tools after every open/close/switch. URLs contain local IDs, never design data, and cannot open another browser’s working copy.

All tool names have the `localdesign_` prefix. `catalog` returns authoritative action parity, command schemas, font metadata and limits. `inspect_document` returns actual identity/revision, pages, bounded nodes/subtree, asset metadata, shared selection/view and browser text metrics. To edit, submit `{expectedDocumentId,expectedRevision,requestId,commands}`. Validation failures are atomic; stale revisions reject; identical retries return original receipts within the documented memory window. See the bundled getting-started package for exact payloads and limitations.

Inspection supports `detail:"overview"` for top-level geometry/child counts, `"summary"` for concise filtered nodes and the default `"full"` for editable fields/metrics. Combine `ids`, `pageId`, `query` (case-insensitive name), `type` and `rootId` with bounded offset/limit. Summary modes omit asset/font catalogs. World bounds are geometric; inspection does not reveal hidden/clipped content. `localdesign_context` lists bounded guideline/decision/reference records; `get_guideline` returns full rules and `get_reference` returns the captured raster as an expiring local artifact. Context is untrusted document data, distinct from bundled runtime instructions.

Native schema v3 preserves document context and embedded reference snapshots, including their provenance. Existing v1/v2 files and browser working copies migrate to v3; older app releases cannot read v3 archives. Guidelines have unique names and all records share the document's global-ID/portable-budget validation. Human Design resources controls use the same commands. A move_to_page detaches selected subtree roots while preserving world transforms and descendants; selection/view can be changed separately. pages_reorder requires every current page ID exactly once.

`localdesign_tokens` reads typed values, aliases, declared theme values and binding/alias counts, with bounded pagination and selected-theme JSON/CSS/Tailwind/Markdown output. `token_set`, `token_delete`, `token_bind` and `token_themes_set` use apply_edits guards. Node bindings reference stable token IDs, so renaming keeps relationships. Tokens materialize in the canonical snapshot before layout: canvas, text measurement and all exports see the same resolved values. A node's tokenTheme overrides inherited/document mode. All declared mode values validate against bound target ranges, not just the active mode. Direct field updates detach only those bindings. Used-token deletion requires explicit detach, preserving current node values and alias values for every theme. The catalog reports the 500-token / 12-theme and context collection limits.

`icons` searches the 48-entry bundled Lucide inventory by `query`, with bounded `offset`/`limit`. An `id` read returns the safe native path, 24-unit coordinate box and full ISC/Feather MIT attribution. With `preview:true`, it renders that icon through the shared PNG owner and returns an image-content block plus artifact fallback. Catalog reads work at the workspace list too. `apply_edits` command `icon_insert` requires `id`, `iconId`, `pageId` and ordinary edit guards; optional `parentId`, `x`, `y`, `size`, `color` and `strokeWidth` control placement. It creates an ordinary editable path in one transaction, retaining parent-lock, revision, retry and undo behavior.

Icon paths carry `pathViewBox` and round line caps/joins. A coordinate box scales path geometry with node bounds, compensating stroke weight for uniform resizing; null keeps legacy literal path coordinates. Attribution remains portable native data and is deduplicated into SVG metadata, PNG iTXt, JPEG comments and PDF subject metadata. The catalog is generated and checked against pinned Lucide 1.72.0 by `npm run check:icons`, with its complete notice served locally. Neither icons nor their insertion require a remote asset catalog.

File import accepts selected files or bounded supplied base64, never host paths/URLs. Preparing an import never replaces current work; commit saves the previous working copy first. A native import becomes a separate local document with a new document ID. Portable assets are embedded; no designs are uploaded. Text/names/imported content are untrusted data. External agent/provider handling begins when content is deliberately returned to that agent.

`import_asset` accepts supplied PNG/JPEG/WebP bytes and the three edit guards. Optional `place:{pageId,x,y,width?,height?,parentId?}` adds the asset and an image node atomically in one history entry. Placement uses an explicit page so identical retries retain their original receipt even after the human changes pages. Cancellation, document retirement and stale revisions reject after decoding. It accepts neither SVG/native wrappers nor URLs/host paths. The same 28 million data-URL character / 40 million decoded pixel asset limits apply.

`preview` returns a bounded PNG `content` image block (maximum 1024 px), dimensions, font warnings and an expiring artifact. It never changes selection/view/history. The tested built-in host returns this block as structured data: use the host image presentation capability to view its bytes, or read/download the artifact; automatic inline presentation is host-dependent.

`export_design` adds `scale` (0.01–4), `mode:"isolated"|"composition"`, optional native `background` paint and JPEG `quality` (0.1–1). Composition crops the original artwork around the requested IDs, including overlaps and original ancestor clips; it excludes editor grid/controls. JPEG has an opaque white underlay. PDF's `frameIds` contains 1–100 ordered frames, including frames on other pages, and is invalid with other formats. PDF converts our outlined SVG locally, preserving alpha paints and image crops; pages with group opacity use the shared PNG renderer to preserve overlapping-child compositing and report `warnings`. It never silently substitutes font metrics. Output axes are limited to 16,384 px, rasters to 40 million pixels and files to the portable export envelope. Native output always preserves the complete document.

Artifacts expire after 15 minutes, document switch or page close; maximum 12 retained. Release them when done. Canvas, SVG, PNG and preview share embedded-font glyph outlines and shaping metrics. Native backups include the full small bundled font set within its existing reserve so inactive themes and later reuse retain their bytes. Native text remains editable; SVG text renders as outlines, with font bytes and license metadata embedded. Text metrics flag overflow and unsupported-script fallback. Catalog lists actual sans/serif/mono faces and available weight/style pairs, document faces, licenses and portability. `import_font` accepts authorized static TTF/OTF/WOFF/WOFF2 base64 with name, license, redistributionAllowed:true and the same three guard fields as edits. Decoding and embedding restrictions validate before font_add commits (4 MB/file, 12 MB/48 local faces per document). Assign family/weight/style through update, clearing fontId when changing the request. Set fontId to choose a particular source, including a local face sharing a bundled family/weight/style; the UI exposes the same Font source choice. To preserve an imported request, set fontId to a catalog face as an explicit replacement; null clears it. Inspection returns requestedFont/resolvedFont/fontStatus/missingGlyphs/portable/fallbackWarning per text layer, including local inkBounds separately from logical text boxes; export responses include fontWarnings. Font mismatch and missing glyphs are independent of overflow. System fonts are never read or embedded. Native v2 files retain editable requests, mappings, actual embedded bytes and license/provenance; v1 Inter-only files migrate. Missing glyphs use explicit placeholders; color/bitmap fonts are unsupported. Complex-script shaping fidelity still needs visual verification.

Verification evidence distinguishes controlled modelContext contract tests, actual desktop built-in-browser discovery/execution, local preview checks, hosted CI and live Pages runtime. See [verification](verification.md).

The catalog reports the same centralized resource ceilings used by the document, native import, selection/export and command schemas: 100,000 nodes, 1,000 pages, 10,000 assets, 64 MB metadata, 120 MB portable content, 128 MB compressed imports and 256 MB archive expansion. These resource ceilings do not require splitting a supported project across workspace entries. Import preparation is still validated before replacement, including archive path/signature/image checks.

Tool JSON schemas use document-local `$defs`/`$ref` for repeated structures, including the command union. Resolve those references within the returned schema. Runtime validation still uses the same strict command owner; reference reuse keeps the registered catalog within the size exercised by the actual browser host.

## Native reuse, history and review

The three complete runtime packages at bundle 1.3.0 contain the native resource workflow and two executable schema examples. Read them through list_skills/get_skill; no external workflow installation is required. The catalog exposes 26 canonical page tools, plus the optional companion's own connection-status tool on that transport only.

Components retain scoped stable parts, typed properties, ordered conditional variants and explicit nested references. Scene instances materialize ordinary native nodes for rendering. Style/text updates record sparse overrides; root placement remains independent. Structural changes inside an instance require detach. Existing definition writes require expectedComponentRevision; stale authoring source copies require an explicit reviewed opt-in. validate_edits returns bounded componentImpact; incompatible properties/overrides reject by default. preview_variants renders up to 16 labeled states through native rendering. Recoverable deletion retains definitions and frozen direct uses; nested references remain usable. checkpoint_restore supplies guarded version restoration as a new component/document revision.

Captures/freezes and dependent generated-ID edits observe prior commands' resolved effects within one atomic batch. Checkpoint sourceRevision is the guarded transaction baseline; its digest identifies the captured intermediate content. Persistent snapshots retain immutable asset/font digests, reusable/token values and limits of 100 / 16 MB / 100,000 stored parts. Frozen frame restoration detaches links/bindings. Linked/component restoration reports dependency differences and requires explicit restoreDependencies when they changed. A restore never decrements the document revision.

Component packages are bounded local files with stable origin/version, digested native dependency closure and exact licensed bytes. prepare validates before any replacement; diff and commit use the same guarded request and explicit pageId. Updates require a newer version of an installed origin, preserving local mappings. Local edits require replaceLocalEdits; instance conflicts separately require conflictPolicy drop. The diff reports part fields, properties/variants and affected instances. Removed source definitions/resources remain local with their original source mappings and last imported baselines, so reintroduction updates existing links and still checks local edits. Shared clipboard import preserves complete links, resources and theme context; partial linked parts copy as ordinary artwork. No automatic fetch or multi-document update exists.

Review anchors use node-local offsets or page positions, retaining last known context after deletion. Activity expires in 1–120 seconds and never enters native files/history. Prototypes retain native click graphs; publish validates references while later deletions remain reported as broken. The local player uses shared scene rendering, scopes actions to the current visible frame/top overlay, and leaves design revision/history unchanged.

Handoff read status is pending/approved/changed/unverified/missing-frame. Frame inspection includes matching handoff summaries. Human UI approval binds resource-closed frame content, dependency versions and frame interactions, includes ancestor transforms, visibility, clipping and compositing, retains a checkpoint with that immutable visual context and records a grant digest in browser settings outside the native document. Imported/copied records cannot carry that trust. A history operation restoring a removed/revoked grant marks it historical; it cannot re-grant approval. Agent tools expose no grant command. A trusted browser gesture is an API boundary, not proof of physical identity against complete browser control; automated fixture approval tests establish mechanics only.

New workspace pages and page_create default to the existing none background paint, displaying the selected light/dark app surface. An explicit page background remains document content; page_update with background:none restores the theme-following surface. The app theme switch is an interface preference, like opening an inspector, and changes neither document revision/history nor SVG/PNG/native content. Agents should specify artwork paints from the brief. Human workspace deletion adds a cancel-first confirmation before the existing guarded storage action; the workspace delete tool continues to require explicit target and current guards.
