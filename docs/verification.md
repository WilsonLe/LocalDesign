# Verification scope

The repository's required release command is `npm run check`: production build (including typecheck, dependency closure/digests, skill budgets and schema-valid example tests), core/file/skill unit tests, and Playwright Chromium journeys against the production preview. The committed CI and Pages jobs run that same command.

The tests exercise atomic batch rejection, stale revisions, identical/changed retries, undo/redo, selection/view separation, hierarchy and rotated reparenting/grouping, frame layout, locks, ordering/alignment/distribution, native archive corruption/unsafe paths/expansion/missing assets/version limits, and schema-valid runtime guidance. Built-browser journeys cover manual drawing/gestures, inspector-driven horizontal/vertical frame layout with gap/padding/alignment and shared undo/redo, inspector-only property patches, text, clipboard, pages/layers, persistence/reload, safe SVG/font substitution/unsafe SVG recovery, PNG/JPEG/WebP, native export and fresh-storage reopen/edit, SVG/PNG output, quota failures with backup/retry, agent/human interleaving, lifecycle retirement, unsupported WebMCP and narrow drawers/focus. Independent-review regressions verify visible group/unclipped-frame output pixels, clipped-frame/hidden controls, reference SVG transform coordinates/pixels, malformed and mismatched native raster rejection, successful >8 MB native metadata export/reopen, atomic over-budget edit rejection, Escape cancellation, newest-save status/unload protection with a held second IndexedDB write, delayed image decoding across page retirement/caller cancellation, cancelled workspace switching, and byte-signature/MIME matching across tool/clipboard/native round trips. Current rendered specimens test text fit and export dimensions; captures are task-owned evidence outside source Git.

Two distinct agent evidence channels are maintained:

- **Controlled cold-start harness:** browser fixtures install a fake modelContext host, discover the production tools, receive only served packages/schemas, author/preview/export/reopen, test unknown versions/IDs, and retrieve guidance offline. This proves the registration/engine/packaging contracts; it does not prove a particular external browser discovers them.
- **Actual desktop built-in browser:** during implementation the browser discovered the registered site tools on the production preview and retrieved the skill catalog and complete getting-started guide through its WebMCP capability. Final authoring/export/reopen and deployed-runtime evidence are retained in the issue/PR release readback. A developer with prior source knowledge is not an independent study of future agent adherence.

The final PR/release evidence binds review, checks and deployed verification to concrete revisions. Do not infer a current production result from this source document alone. A GitHub Pages HTTP response or successful job is checked separately from manual controls, actual tool calls and native-file interoperability.

Known limits: Chromium is the automated browser; other engines/devices are not claimed. Static text metrics do not establish all script/glyph shaping; bundled sans/serif/monospace faces cover Latin/extended Latin/Vietnamese; imported font coverage is checked from its character map. Safe SVG import is intentionally narrow and not a general SVG export round trip. There is no multiplayer merge resolution; each browser tab has its own working state. IndexedDB compares the last observed saved copy transactionally and rejects conflicting writes from another tab, preserving both the existing saved data and the unsaved active view. Export a backup or use Save a copy to recover. History/receipts are memory-only; browser storage is not a portable backup. LocalDesign is a small design editor, not complete Figma compatibility.

Font regressions use licensed static OTF/TTF fixtures plus pinned WOFF/WOFF2 subsets. They verify real family/weight/style/coverage, embedding restrictions, corrupt/oversized/expanding input, atomic guarded history, native v1 compatibility, explicit missing-font mapping, glyph warnings independent of overflow, wide/narrow manual controls, cancellation after decoding, and font-bearing clipboard transfers. The source selector also chooses an imported face when a native working copy retains a bundled face with the same family/weight/style. A native round trip preserves both that explicit choice and an automatic bundled choice in the same document, comparing nodes, metrics and PNG pixels; malformed order metadata rejects before replacement. An unavailable 500 weight also keeps the same 400 fallback when a preceding layer uses 600, proving collection order cannot change fallback ties. Independent-review regressions cover selected italic/diacritic ink and clipping, button-focused dialog shortcuts with native input undo, shared-renderer preview glyphs/subset precedence, and narrow NFC/NFD wrapping/pixels. The built-browser specimen compares canvas pixels against embedded-font SVG/PNG/preview and checks identical wrapping/metrics/PNG after fresh-storage offline native reopen. These comparisons establish the tested faces/text in Chromium, not exact system-font equivalence for the original website.

Actual built-in-browser verification additionally discovered and executed the page tools, selected a replacement through the UI, changed/undid style after native reopen, and inspected exported pixels. Its image decoder produced blank text with embedded SVG web fonts even after Chromium’s data-URL warmup passed. The shared outline renderer removes that dependency. Current candidate screenshots/artifacts remain outside Git; hosted CI, merge and deployed evidence are separate.

The original wilsonle.me v1 archive was also opened in a disposable Chromium context: six pages, 1,028 layers, 550 text layers already declared as Inter. Its nine embedded Inter subsets match the current pinned bytes. Six representative home headings and four labels were restored from the observed CSS family stacks and explicitly mapped to portable substitutes while preserving text, position, boxes, size, tracking and line height. The source archive checksum stayed unchanged. Some fitted legacy headings overflow after mapping; no silent fitting was applied, and exact Iowan Old Style / SFMono-Regular fidelity is not claimed. The legacy conversion had already discarded font requests, so those cannot be recovered automatically from that file.

Font advance references are generated independently with HarfBuzz and pinned by font-file SHA-256 in tests/fixtures/fonts/shaping-reference.json. macOS and Linux browser CSS measurements differ because they are a separate rendering path; the product uses unhinted embedded-font shaping/outlines. CI therefore asserts the independent design-unit references and actual exported pixels rather than requiring OS CSS metrics to be identical.

Large-project coverage (issue #7) imports a synthetic 17,716-node/206-page/656-asset archive into the engine, edits a selection beyond the old node cap and verifies undo. Built-browser coverage opens, edits, persists/reloads and exports/reopens a 4,201-node/206-page/257-asset scene, then rejects an over-limit replacement without losing the working copy. A combined native-import regression retains the full 10,000-image catalog plus 48 three-file local fonts, so the archive entry budget covers both resource kinds. Count and byte ceilings remain finite and share one owner in `src/core/limits.ts`; image, path, expansion, hierarchy and schema safeguards remain enforced. A separate task-owned Silebot archive supplies actual built-in-browser evidence; user designs are not committed as test fixtures.

Use `LOCALDESIGN_TEST_PORT=4198 npm run check` for an isolated test listener when the default port belongs to another checkout. The override is validated as an integer port and applies to both the preview command and test base URL.

Independent PR #8 review reproduced a JavaScript argument-stack failure in bounds for 40,000 visible rectangles below the new ceilings. Bounds now reduces corner extrema iteratively; a regression validates and fits that scene without spreading coordinate arrays. Existing rotated/stroked/group/clipped export journeys retain the consumer checks. The large-scene ceiling is not a guarantee of device performance or unlimited per-gesture command counts.

Layer-navigation coverage (issue #10) uses a synthetic tall Hero/Selected work/Get in touch/Footer profile and a distant rotated nested workspace at 1440, 1000 and 390 px. It checks clear canvas bounds against the floating controls, stable repeated activation, Shift/keyboard selection, drawer dismissal/focus, hidden/locked controls, group and frame clipping bounds, and unchanged nodes/revision/history. Panel display sorting is checked separately from scene paint/auto-layout order; served cold-start packages include the organization/finishing guidance. These fixtures do not establish future agents' adherence to the guidance.

Sidebar overflow coverage (issue #12) creates 60 pages and 40 layers, then uses real wheel scrolling to reach both lists’ final rows at wide, intermediate, narrow and short landscape viewports. It checks visible headings/search/Add page, keyboard page activation, layer search/selection, empty pages, add/delete, and unchanged scene/revision/history during navigation. The Layers heading viewport assertion fails against the original layout before the fix. Existing editor journeys retain single-page and drawer-control coverage.

Large-workspace performance coverage (issue #14) seeds disposable IndexedDB with 6,000 nodes across 200 pages, including 100 frames / 2,100 active-page layers and 400 text nodes. It measures production-browser open, pan, search, selection, drag/save, subtree inspection and selected SVG export; the regression budget permits CI variation while rejecting the measured ~1.3-second pan baseline and unbounded layer DOM. Keyboard Home/End and Tab across unmounted windows, focused-row retention while scrolling, offscreen search, single-history gesture/undo and durable-save acknowledgment have separate assertions. Existing large-document/native and typography pixel journeys remain required. These synthetic timings describe the tested machine/workload, not every device or scene distribution; no real user design is modified.

Independent PR #15 review additionally reproduced stale font previews when Fonts was opened before bundled-font readiness and a quadratic flat-root marquee introduced by building a traversal index per candidate. Inspector now receives readiness explicitly, and marquee shares a fresh index across its candidate loop. Regression journeys hold/release font requests while keeping the dialog open and select all 6,000 roots without creating a document revision or history entry.

The engine's ID lookup map lives only for one atomic edit transaction and follows structural changes in that batch. Regression tests cover create/duplicate/group/ungroup/reparent/delete/recreate/update, rejection after deletion without active-document changes, page-owned ID removal/reuse, and a full 500-create batch in a 20,000-node workspace followed by undo. This avoids rebuilding a full index per command without retaining stale entries across transactions.

Issue #16 adds interactive viewport filtering. `tests/browser/viewport-performance.spec.ts` uses a disposable 10,100-node/5,000-text multi-screen board and checks mounted DOM, frame timings, offscreen layer activation, saved edits/reload and complete selected SVG output. `tests/visibility.test.ts` covers rotated/overflowing ancestors, hidden/clipped branches, out-of-box paths and stroke edges. Low-zoom warm pan timings are also bounded, and packed text paths are compared with the original outlined renderer for pixel error/coverage, overlap, transparency and stroke; tests/compact-glyphs.test.ts checks bounded outline expansion. An optional `LOCALDESIGN_PRIVATE_FIXTURE` JSON working-copy path permits local comparisons without committing design data; `LOCALDESIGN_BASELINE=1` records the old renderer without asserting the new mounting contract. Use separate Playwright output directories for concurrent baseline/candidate runs. These harness measurements do not replace deployed built-in-browser checks.

Issue #18 covers cold first visits separately from warm navigation. `tests/browser/cold-navigation.spec.ts` reloads before measurement, then retains the first overview zoom, unseen vertical dense regions and every page switch without dropping early samples. Its public fixture matches repeated-label/text-length distribution and uses irregular text sizes; the optional private fixture stays outside Git. `LOCALDESIGN_PROFILE=1` additionally writes a CPU profile; ordinary latency checks run without sampling instrumentation. `tests/fast-layout.test.ts` compares all pinned bundled faces/subsets, individual prefix glyph positions/advances, NFC/NFD narrow wrapping and negative/positive tracking with the previous exhaustive shaper. Controls/default ignorables, missing glyphs and complex-script fallback have explicit cases. The packed/detailed pixels, delayed-font readiness, durable edits, native round-trip and complete exports remain separate required browser journeys. The local cold-navigation target is 250 ms; shared Linux CI uses a separate 500 ms regression ceiling after measuring about twice the workstation latency (~395 ms versus ~197 ms on the same public fixture). Both retain every first sample and reject the multi-second baseline; neither is a universal device guarantee. Final CYOBot acceptance is measured separately in the actual built-in browser.

Workspace-route coverage (issue #20) starts at a truly empty list without creating a saved document. `tests/browser/workspace-routing.spec.ts` verifies create/open/import/save-copy/close URL synchronization, saved node/name reload, Back/Forward, missing/unknown paths without reopening the last design, tool retirement, deletion of the final closed design, keyboard focus and 44 px delete targets at 1440/900/390 px, and failed-save backup/retry while navigation retains the working copy and matching URL. Independent-review regressions exercise Back before blur for design/page names, text content and numeric geometry; retire export dialogs on history close and tool-driven switching; reject export with no active document; and remove obsolete navigation alerts after a successful save retry. Tool close/create/open/save_copy/import tests retain focused text drafts, reject the pre-commit revision guard, and verify reopen after a fresh guarded retry. A held IndexedDB transaction additionally exercises text typed while tool close is waiting for a save; the switch rejects and keeps the committed text in the active workspace. A Pages-style HTTP-404 response serves the emitted `404.html` and loads its absolute asset URLs before reopening/reloading the saved document; this is a local static-host simulation, separate from a deployed Pages result. `tests/workspace-route.test.ts` covers application-base and malformed-path handling. Existing IndexedDB performance fixtures navigate to the seeded document ID explicitly; the legacy active setting is no longer routing authority. Cold-navigation measurement additionally waits for the routed Canvas to mount, preserving every first zoom/unseen-area/page sample and both existing timing ceilings; a save-status acknowledgment alone is not route readiness.

The actual desktop built-in browser separately discovered the root's WebMCP tools with documentOpen:false, created a disposable workspace at its own path, applied a shape through the discovered tool, returned to the list through the UI and reopened/reloaded the saved shape at that path. Existing browser designs were left untouched. Candidate screenshots and detailed logs remain outside Git; this local evidence does not establish hosted CI, merge or deployed behavior.

Native icon coverage in `tests/icons.test.ts` and `tests/browser/icons.spec.ts` checks guarded insertion/parent locks/history/atomic failure, all 48 pinned source geometries, bounded search/preview and unchanged read state, wide/narrow human search/resize/keyboard controls, and offline native reopen with identical PNG bytes. Each icon's painted coverage and pixel difference is checked separately so a blank or wrong small icon cannot hide in the specimen average. PNG notices are parsed by the independent strict PDF image reader; PNG/JPEG/SVG/PDF/native outputs retain source notices. When local Poppler is available the test independently renders actual vector PDF pages and compares each icon's pixels/coverage. Hosted CI without Poppler still validates the PDF's content/metadata; this does not claim a deployed browser result.
