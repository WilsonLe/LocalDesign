# 0005 — Optional authenticated loopback MCP companion

Status: accepted within the user's complete F12 implementation/release authorization in issue #23. Extends ADR 0001's page-only transport boundary; native authoring, storage and rendering stay in the browser.

Before integration, the official `@modelcontextprotocol/client` 2.4.0 SDK discovered a probe tool through `serveStdio` from `@modelcontextprotocol/server` 2.4.0. The actual Codex in-app browser opened a local probe page and completed a WebSocket echo over 127.0.0.1. This establishes the named client's stdio/browser transport path. Full tool/lifecycle, HTTPS Pages and deployed acceptance remain required; it does not establish every MCP host or browser combination.

An opt-in Node companion exposes standard MCP over stdio and binds its browser socket to 127.0.0.1 only. Each process generates a fresh 256-bit session code, shown on stderr for the operator to enter in Connect agent. Never store it in a URL, document, browser storage or provider account. Validate the WebSocket Host, Origin and exact bridge path before upgrading; accept only the production Pages origin or loopback development origins. Require the code before accepting a catalog, permit one attached browser, bound payloads/in-flight requests and close unauthenticated connections promptly. There is no HTTP MCP server or network-facing listener.

One PageToolRuntime owns the active browser's existing tool implementations, artifacts, epoch and abort lifetime for both WebMCP and the companion. Catalog updates retire pending operations and notify the standard client. Requests carry that epoch; forward arguments and cancellation to the same page owner, including document/revision guards and idempotent receipts. Closing/switching the document or page cannot leave a stale mutation channel. The companion never loads a second editor, reads host design paths, uploads designs or runs a model. Data deliberately returned through tools reaches the explicitly connected local MCP host.

Use pinned official SDK packages for protocol negotiation/tool schemas and pinned ws for transport. Their Node-only dependencies are not imported by the Vite application. Node follows .nvmrc; the launch command uses its TypeScript stripping flag solely to read the shared pure-data core resource limits. Keep diagnostics on stderr, protocol traffic on stdout, and publish no session code through a tool. Document actual supported-client results and connection recovery instead of claiming universal MCP compatibility.

The sign-off grant remains a separate trusted human-interface action and browser-local registry. Neither transport receives a grant command. A caller with complete script/UI control of the browser can impersonate gestures; this boundary restricts the exposed tool API, rather than claiming proof of the operator's physical identity. Approval tests use disposable fixtures and establish mechanics, not actual user approval of a design.
