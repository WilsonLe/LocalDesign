# 0004 — Native agent capabilities and portable document extensions

Status: accepted for [issue #23](https://github.com/WilsonLe/LocalDesign/issues/23) by the user's 13 November 2026 implementation, merge and deployment request. Supersedes the initial-release feature exclusions in ADR 0001 for the specifically recommended native features. The browser-local architecture, safe import boundary and shared renderer remain.

The complete scope is maintained in [the integration decision and delivery document](../agent-tool-integration.md). Implement the ready equivalents and recommended features, including later themes, components, checkpoints, local review, page organization, local outputs, native icons, prototypes, portable component packages and human approval. Exclude the ignored integrations and cloud/provider services. Use browser WebMCP for agent access. [ADR 0005](0005-optional-loopback-mcp-companion.md) records the transport decision.

Document schema v3 starts with bounded guidelines, decisions and reference snapshots pointing at embedded raster assets. These are editable user data; they do not become executable instructions. Context records, page ordering and cross-page movement are canonical commands using the same atomic validation, global IDs, history and guards as existing operations. Reads provide bounded metadata/full retrieval through WebMCP. Pinning a selection renders through the existing PNG owner, validates the produced raster and commits the asset/reference atomically with the pre-render guard.

Typed document tokens use stable IDs for bindings/aliases, named theme overrides and per-node inherited mode selection. Materialize resolved native fields before canonical auto layout, so existing scene/text/export owners consume one representation. Literal edits detach the changed binding; an explicit used-token delete freezes its current bound values and preserves every alias mode. Validate aliases, names, theme references and every bound property range across declared modes before commit. Keep node-hierarchy depth separate from the bounded token graph: token cycle detection must not depend on catalog insertion/cache order.

The small icon catalog is compiled from pinned, licensed Lucide data into validated native path commands, never injected SVG markup. Keep a fixed source inventory and reproducible build-time check. Native paths can carry an explicit coordinate box and stroke caps/joins while old paths retain literal-coordinate behavior. Icon insertion preserves complete attribution in the native node; outputs deduplicate notices into their supported metadata without changing pixels. This uses the existing engine and renderer, with no remote catalog or new asset service.

Native backups include the complete small bundled font catalog within the existing reserved byte/count envelope, plus document-local faces. Capturing only currently rendered text loses fonts needed by an inactive theme or future reusable-definition insertion. Preserve resolver order and validated bytes/provenance; an unknown bundled identity still rejects explicitly. SVG/PNG/JPEG output retains the current render's normal font collection path.

Extend v3 explicitly as the unreleased candidate gains its approved feature families. Migrate v1/v2 files and browser working copies through the document validator without losing node/font identity or content. Native font catalogs and resolver-order files apply to v2 and newer archives; do not tie their decoding to one current schema literal. Unknown future versions reject before replacement. Older releases cannot open v3 archives. Preserve working copies and portable backups rather than silently downgrading.

Keep one stored native representation and shared resolution/rendering pipeline. Adding a parallel HTML document/renderer, unsafe SVG insertion, hosted assets or vendor import services would weaken the core ownership and portability model and remains excluded. General skills stay static and versioned; document-specific context travels with the design. New UI belongs in concise progressive controls and the existing neutral component system. No initial templates or unrequested design content is inserted.

Local PDF output lazily loads pinned jsPDF/svg2pdf to convert only our own outlined scene SVG. No external stylesheet/image loading is allowed. Normalize native alpha paints and browser-decoded raster bytes before conversion, and explicitly clip image viewports. Converter paint alpha does not implement SVG's isolated group compositing: use the shared PNG renderer for those pages at the selected scale, with a visible/tool warning. This preserves the rendering contract rather than accepting a valid PDF with different pixels. Native/SVG/PNG/JPEG and composition crops continue to use the same scene/font owners; an explicit ordered frame list defines multipage PDFs.

Component implementation contract: store a library definition as a native frame/group subtree with scoped stable part IDs, typed properties, conditional variants and explicit nested references. Capture a selection to create/update a definition; an editable source copy is ordinary native artwork with part provenance, published explicitly through the canonical command. This keeps editing through existing canvas/inspector controls without a second renderer or hidden editor mode. Library definitions are the reusable source of truth, while linked scene instances materialize ordinary native nodes for the shared renderer.

Instance roots hold property values and sparse field overrides. Generated descendants have deterministic IDs and stable part paths, including nested reference paths; ordinary property edits record overrides, reset removes them and detach keeps the current native content. Structural edits inside a linked instance require detach. Validate all definitions, references, property defaults/options, variants and overrides atomically. Definition changes expose bounded impact and conflict information; incompatible overrides reject unless the caller explicitly chooses to drop them. Human controls use the same commands and an impact/apply step for changes affecting instances.

Deleting a library definition is recoverable: retain its data, freeze retained direct instance links unless explicitly detached, and keep nested references able to use the retained definition. Restoration reactivates eligible links and checks name collisions. Detached content stays detached. Persistent frame/component versions follow in F04; version restoration is a new revision with explicit dependency/override reconciliation. Count stored definition parts and scene nodes under the existing native node and byte ceilings; source/instance helpers do not bypass locks, guards, history or import validation.

Consequences: persistent additions consume the existing metadata/portable-content budgets and must validate references, IDs and collection bounds. Native format, human controls, tools, output behavior, examples and recovery evidence must advance together. Approval must bind rendered content/dependency versions; components, tokens and prototypes cannot claim readiness from schemas alone.

Evidence starts with context/page atomicity, migration, rotated subtree movement and filtered inspection in `tests/context-pages.test.ts`, plus human context capture/native reopen, page controls and tool discovery contracts in `tests/browser/context-pages.spec.ts`. Final acceptance and deployed evidence remain on the delivery owner.

Rollback: revert through the reviewed release process while preserving browser working copies and v3 backups. An older app must reject unsupported v3 content explicitly; never clear storage or remove unsupported fields as a downgrade.

Persistent checkpoints store bounded native frame/component parts, reusable/token dependency values and immutable asset/font digests. Retain at most 100 checkpoints / 16 MB compact metadata / 100,000 stored parts, within the overall portable budget; reject atomically rather than silently evicting. Frozen frame restoration detaches current links and token bindings while keeping captured literal artwork. Linked/component restoration reports changed dependencies and requires an explicit document-wide dependency restore choice; every component restore advances its current revision. Restore uses ordinary guarded transactions/history. Stored captures share existing IndexedDB save/backup/retry and native archives.

Local review threads retain page/node context and last world coordinates, including after an anchor disappears. Replies and resolve/reopen are ordinary guarded document edits. Agent activity is a separate transient engine state, visibly labeled, limited to 120 seconds and reset on document replacement; it never enters native files or undo history. Actor labels are user data, not authenticated identities.

Human handoff keeps grant authority outside imported design data. Only a fresh trusted UI event can call the engine's separate approval path, which validates/captures the frame, persists a browser-local grant digest and then rechecks the unchanged document before committing. Failure leaves the pending request/design unchanged. Requests, revocation and removal are canonical commands. Granting approval requires the human interface. Sign-off hashes the resource-closed native frame and interactions, keeps an approved checkpoint and invalidates on changes. Imported records lack local trust. History restoring a removed/revoked/undone grant marks it historical, retaining evidence without re-authorizing it. Labels are not authenticated identities; complete browser script/UI control can impersonate a gesture.

Capturing/freezing commands and edits to newly generated parts resolve preceding transaction effects before consuming them. Keep one transaction index and settle only at those dependency boundaries, collecting bounded conflicts/warnings into the final receipt. This preserves batch atomicity, single-step history and current-value snapshots instead of capturing a stale materialized cache.
